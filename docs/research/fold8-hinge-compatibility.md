# Galaxy Z Fold8 hinge compatibility

Checked 2026-10-13.

The regular Galaxy Z Fold8 exposes Android's public `TYPE_HINGE_ANGLE` sensor in published firsthand tests. `expo-hinge` uses that same API, so basic hinge readings should work. The tested Fold8 reports only 0°, 90° and 180° through the public sensor; a continuous, precise angle stream is not established. This is a compatibility inference from device measurements and matching source code, not an `expo-hinge` test on a physical Fold8 by this session.

- Folio identifies its development phone as the regular Galaxy Z Fold8, SM-F971U, Android 17 / One UI 9. Its developer reports an October 6, 2026 measurement with three distinct public sensor values. Its implementation explicitly records 0°, 90° and 180° behavior and registers a `TYPE_HINGE_ANGLE` listener. [Device identification](https://github.com/McCal-Codes/folio/blob/df5abd8e9d3ad3756fc705d55ed267de66285a1a/README.md), [measurement report](https://github.com/McCal-Codes/folio/blob/df5abd8e9d3ad3756fc705d55ed267de66285a1a/docs/adr/0012-root-hinge-provider.md), [public sensor implementation](https://github.com/McCal-Codes/folio/blob/df5abd8e9d3ad3756fc705d55ed267de66285a1a/app/src/main/java/com/mccal/folio/FoldTransition.kt), [angle handling](https://github.com/McCal-Codes/folio/blob/df5abd8e9d3ad3756fc705d55ed267de66285a1a/app/src/main/java/com/mccal/folio/HingeTracker.kt).
- An independent Samsung Remote Test Lab capture identifies another regular Fold8, SM-F971N. The probe uses `getDefaultSensor(Sensor.TYPE_HINGE_ANGLE)` and records events. September 22 and 27 captures show 180° on both cover and main displays, including a `HALF_OPENED` posture. These confirm that the public sensor delivers readings, but the constant value does not demonstrate accurate angle tracking in RTL. [Fold8 measurement conditions](https://windowinsets.info/galaxy-z-fold8), [closed capture](https://github.com/easyhooon/windowinsets.info/blob/3884efc51ee56798d139ae64d730719b1083573c/measurements/galaxy-fold/galaxy-z-fold8/recapture-2026-09-22/cover-threeButton.json), [half-opened capture](https://github.com/easyhooon/windowinsets.info/blob/3884efc51ee56798d139ae64d730719b1083573c/measurements/galaxy-fold/galaxy-z-fold8/recapture-2026-09-27-rotation/main-portrait-1-threeButton.json), [probe source](https://github.com/easyhooon/windowinsets.info/blob/3884efc51ee56798d139ae64d730719b1083573c/tools/insets-probe/app/src/main/java/info/windowinsets/probe/MainActivity.kt).
- ZFoldDuo reports continuous Fold7/Fold8 tracking using Samsung's private wallpaper service through on-device Wireless Debugging. Its code polls private service commands and parses `mCurrentAngle` from logcat. That is separate from Expo's public sensor API and does not prove Expo can receive the same precision. [ZFoldDuo documentation](https://github.com/nnnnnnn0090/Z-Fold-Duo-TEST/blob/c8da65d5f8bba036ddeb17b491e7e8fa3d6ab0b1/README.md), [private angle client](https://github.com/nnnnnnn0090/Z-Fold-Duo-TEST/blob/c8da65d5f8bba036ddeb17b491e7e8fa3d6ab0b1/app/src/main/java/com/foldduo/hinge/EmbeddedAdbAngleClient.kt).

- Samsung announced Galaxy Z Fold8 and the separate Fold8 Ultra on July 22, 2026. Its current US Fold8 product page offers the phone for sale. [Samsung announcement](https://news.samsung.com/ca/samsung-introduces-all-new-foldable-lineup-galaxy-z-fold8-ultra-fold8-and-flip8), [Samsung US product page](https://www.samsung.com/us/smartphones/galaxy-z-fold8/).
- Android added `TYPE_HINGE_ANGLE` in API 30. Its event reports degrees in `values[0]`. Apps must check for the sensor at runtime; `getDefaultSensor` returns `null` when unavailable. [Sensor reference](https://developer.android.com/reference/android/hardware/Sensor#TYPE_HINGE_ANGLE), [SensorEvent reference](https://developer.android.com/reference/android/hardware/SensorEvent#values), [sensor discovery](https://developer.android.com/develop/sensors-and-location/sensors/sensors_overview#sensors-identify).
- The Android compatibility definition requires supported hinge sensors to provide at least two readings. This does not guarantee a smooth stream of intermediate angles. [Android sensor requirements, section 7.3.13](https://android.googlesource.com/platform/compatibility/cdd/+/master/7_hardware-compatibility/7_3_sensors.md).
- Samsung says Flex mode is unavailable on the regular Fold8 and documents it on Fold8 Ultra. Flex mode is a Samsung app and posture feature; this does not prove that Fold8 lacks raw angle events. One Samsung Flex mode article also contains a contradictory model list. [Samsung opened/closed guide](https://www.samsung.com/us/support/answer/ANS10003219/), [Samsung Flex mode guide](https://www.samsung.com/us/support/answer/ANS10003223/), [Fold8 Ultra guide](https://www.samsung.com/ca/support/mobile-devices/use-flex-mode-on-your-samsung-galaxy-z-fold8-ultra/).
- Expo's current package source identifies `expo-hinge` as 58.0.1. Android's `isAvailable` checks API 30 or later, but its observer exits when the hinge sensor is missing, before starting either angle events or WindowManager posture collection. Therefore, `isAvailable === true` alone does not confirm hardware support. [package metadata](https://raw.githubusercontent.com/expo/expo/main/packages/expo-hinge/package.json), [Android observer](https://raw.githubusercontent.com/expo/expo/main/packages/expo-hinge/android/src/main/java/expo/modules/hinge/HingeObserver.kt).

The local hinge example has separate iOS and Android screens with shared session logic. The Android screen passes the [foldable emulator checks](../testing/hinge-android.md). The decisive Fold8 check is still a native Android build with an angle listener, then folding the actual phone and checking which events arrive.
